Use db push instead of migrate deploy in the Vercel build

prisma migrate deploy fails with P3005 against the existing database: the
schema was created with db push, so there is no migration history to
baseline against. Vercel keeps serving the last successful deployment when
a build fails, which is why the live site still showed the old UI.

Go back to db push but keep the two fixes that actually mattered:
--accept-data-loss is gone (a lossy schema change now fails the build
loudly instead of silently dropping columns), and the build no longer runs
prisma db seed, which force-promoted the admin account on every deploy.

Drops the 0_init migration. Adopting versioned migrations later needs a
one-time `prisma migrate resolve --applied 0_init` baseline first.
